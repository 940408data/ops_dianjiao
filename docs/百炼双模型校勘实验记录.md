## 三、实施过程（按时间线）

1. **主仓库离线成果落盘**：`.gitignore` 排除 1.2GB 书影 PDF/zip，commit + push 到 `main`。
2. **建 worktree `llm-collation`** 隔离实验，避免污染 main。
3. **百炼连通测试**：4 模型均可通。关键发现——deepseek/glm/qwen3.7 是**推理模型**，返回 `reasoning_content`（思维链）+ `content`；`max_tokens` 太小则 content 被思维链占满而截空。
4. **改造 `OpenAICompatClient`**（`guji_collator/agents.py`）：
   - `max_tokens` 参数（保证 content 不截空）；
   - `enable_thinking` 参数（关思维链加速）；
   - `complete_vision()`（多模态 `image_url`，无真图时退化文本层）；
   - `_post()` 退避重试（防限流/超时把整轮 run 弄崩）。
5. **冒烟验证**：deepseek `max_tokens=4096` 即通；glm 需 `16384` 才不截空。两模型均返回真·LLM 文言按语（非规则模板）。
6. **第一次全书 run 失败**：用 agent 派发跑全书，glm 开思维链单条 ~16s，616 次调用需数小时，**agent 内 Bash 的 600s 超时上限把 run 进程 kill**（日志末尾 `[killed]`，S4 合议未完成，无 run_report）。
7. **诊断**：①glm 思维链过长；②agent 内 Bash 有超时上限，不适合长 LLM 批任务。
8. **解决**：client 级**关思维链**（deepseek 6.5→1.5s、glm 15.8→2.1s，且 content 不再截空、可回落到 4096）；改用 **detached 后台任务**（`run_in_background`，超时自动转后台跑到完，不被 kill）。
9. **重跑成功**：两 run 均完成（exit 0）。
10. **视觉能力实测**：pdftoppm 把当涂郡本书影 PDF 转 PNG，发多模态请求——qwen3.7/3.8/3.6 **都能准确识别竖排繁体书影**（还分析异体字/避讳/破损），纠正了"qwen3.7 是纯文本模型"的误判。
11. **真书影复核工程化**：`qwen_visual_recheck.py`——对悬置形近字，用其上下文在当涂郡本各页 OCR 中**定位书影页** → pdftoppm 转图 → qwen3.7-plus **整页看图断字**。
12. **三方对比与裁断**（见下）。
13. **normalize 补高频异体字**（旣閒丗髙乗乆彞頽内强鬪刼爭㓜隂吕），消除"假分歧"噪声。
14. **commit 实验**（`8e6584f`）；8127 产物服务改用 **nohup** 持久化（`run_in_background` 常驻任务会被回收）。

## 四、实验结果

### 4.1 双模型裁断统计

| | deepseek-v4-flash | glm-5.2 |
|---|---|---|
| 改字 | 38 | 14 |
| 仍旧 | 82 | 91 |
| 悬置 | 34 | 49 |
| 自动决议率 | 77.9% | 68.2% |

**chosen 一致 63 条（40.9%），分歧 91 条（59.1%）**；分歧类型：实质异文 52、脱文 29、衍文 7、形近 3。

### 4.2 形近字三方仲裁（qwen3.7 书影 = ground truth）

10 条悬置形近字：**deepseek 判对 5，glm 判对 5（打平）**。
关键：D0006/D0086/D0088 等，书影明确是 OCR 误识（曰→日、巳→己、已→己，应改），但两模型都保守选"兩存"；D0041 脩书影确认是底本原字（应存），deepseek 判对、glm 误判。

### 4.3 裁断结论

- **两模型判断力打平，区别在性格**：deepseek 果断（多自动决议）、glm 保守（多悬置）。
- 表面 59% 分歧，主要是**异体字噪声**（normalize 表未收录，且同一模型对同一异体字自相矛盾）+ **保守度差异**（一方兩存/悬置 vs 另一方定案），真正"改 A vs 改 B"的硬冲突很少。
- **glm 输出格式问题**：chosen 字段有时写成整句按语（"補…八字""刪「爭」字"），不守"候选读法"约束，需清洗。
- **视觉复核是刚需**：文本模型对低置信形近字只能兩存/猜，qwen3.7 看书影能一锤定音，且能防"误改底本原字"。

### 4.4 补异体字后的真实分歧率（重跑）

normalize 补 16 个高频异体字后重跑（异文 154→106，实质异文 87→38）：

| | deepseek | glm |
|---|---|---|
| 改字 | 30 | 19 |
| 仍旧 | 43 | 49 |
| 悬置 | 33 | 38 |
| 自动决议率 | 68.9% | 64.1% |

**chosen 一致 45 条（42.5%），分歧 61 条（57.5%）**；分歧类型：脱文缺字 29、实质异文 18、衍文重出 10、形近 4。

要点：
- **实质异文分歧 52→18**：异体字噪声消掉大半（残留的 僣/僭、綿/緜、緑/綠、况/況、滛/淫、咏/詠、眞/真 仍是未补的异体字）。
- **总分歧率 59.1%→57.5%，仅微降**：两模型分歧的"主战场"不在异体字，而在**脱文缺字（○重文号/分节符处理）与衍文重出（衍文删/存）**——这是真实的判断哲学差异：deepseek 倾向兩存/删，glm 倾向保留底本/具体处理。
- 61 条分歧里大量仍是"一方兩存 vs 另一方定案"（保守度差异），非"改 A vs 改 B"的对立。
- glm 的 chosen 格式问题依旧（把按语/正文写进 chosen）。

## 五、踩坑与技术要点（复现必读）

| 坑 | 解决 |
|---|---|
| 推理模型 content 截空 | `max_tokens` 给足；或关思维链后 4096 即可 |
| glm 开思维链太慢（单条~16s，全书数小时） | `enable_thinking=False`（提速 4–8 倍），统一 4096 |
| agent 内 Bash 600s 超时 kill 长 run | 长 LLM 批任务用 **detached 后台任务**，不靠 agent |
| `run_in_background` 常驻服务被回收 | HTTP 服务用 **nohup** 脱离任务生命周期 |
| PlainTextEngine 无真 bbox | 视觉复核用"定位书影页→整页送 qwen"近似；真·单字裁切需真实 OCR |
| 环境分类器间歇超时 | 只读/文件操作不受影响；执行类命令重试赶上恢复窗口 |
| worktree 隔离拦复杂命令 | 拆成无管道、无 `cd abs &&` 的简单命令 |
